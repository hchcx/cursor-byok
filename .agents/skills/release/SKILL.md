# Fork desktop releases

This fork publishes from `.github/workflows/release.yml`. User setup and release instructions are in `docs/fork-updates.md`.

## Authority and secrets

- Local inspection, preparation and edits do not authorize remote publication.
- Require an explicit instruction before pushing a version-increasing commit to `main`, rerunning a publishing workflow, editing a GitHub Release, or configuring repository Secrets.
- Before remote mutations, verify the remote is `hchcx/cursor-byok` and the authenticated GitHub identity is authorized by the repository owner. Never publish to the original author's repository.
- Never print, commit or upload `.tauri/cursor-byok.key`, except to `hchcx/cursor-byok`'s `BYOK` Actions Secret (mapped to Tauri's `TAURI_SIGNING_PRIVATE_KEY` environment variable) with explicit authorization. The current key has no password; do not configure a password Secret for it.
- Never replace a signing key, move an existing tag, overwrite a published version, or disable signature verification to bypass an error.
- Do not run application compilation/build commands without explicit user authorization, and do not start a development server.

## Publication policy

- A push to `main` publishes only when the desktop version increases relative to the pre-push commit. Ordinary commits never publish.
- The version must be stable `MAJOR.MINOR.PATCH`; beta/prerelease versions are not part of this fork's release process.
- Keep all five version files consistent using `node .github/scripts/desktop-version.mjs set VERSION`. This updates manifests and locks without building or publishing.
- The workflow creates `v<version>` at the exact pushed commit through `tauri-action@v1`'s `releaseCommitish`. Do not push release tags manually; tag pushes are not release triggers.
- All platforms first upload into a draft. Publish as Latest only after all platform builds and updater manifests complete. Keep `prerelease: false` because the clients use GitHub's `/releases/latest/download/` URLs.
- Existing tags belonging to another commit must cause a failure. Use a new version rather than deleting or moving tags.

## Sources and verification

- Standard updater: `apps/desktop/src-tauri/tauri.conf.json`, endpoint `https://github.com/hchcx/cursor-byok/releases/latest/download/latest.json`.
- Windows portable updater: `apps/desktop/src-tauri/src/update/mod.rs`, endpoint `https://github.com/hchcx/cursor-byok/releases/latest/download/portable-latest.json`.
- Both updater paths use the public key in `tauri.conf.json`. It must match the backed-up private key used in Actions and local desktop builds.
- Preserve the signed Windows ZIP and `portable-latest.json`, standard signed Tauri artifacts and `latest.json`, and the existing `update.json` publication assets. These are already generated by the workflow; do not add new update clients.
- `tauri-action@v1` uses `uploadUpdaterJson: true`, not `includeUpdaterJson`.
- First installation of the fork must be manual: already-installed original-author builds still contain the old endpoint and public key.

## Local preparation

1. Preserve unrelated user changes and inspect the current branch and remote.
2. Configure only the two fork updater endpoints and the fork public key. Never commit private key material.
3. Synchronize version files with the version script only when a version bump is requested. Leave `cursor-server`'s independent version unchanged.
4. Run `node .github/scripts/desktop-version.mjs check`, lightweight release-script tests, and `git diff --check`. These do not compile the application.
5. Validate workflow YAML and inspect the exact diff. Confirm `.tauri/` is ignored.
6. Only with separate explicit build authorization, run desktop build/type checks. Only with separate publication authorization, commit and push the release set to `main`.
7. After an authorized release, verify its tag points at the intended commit, the release is not draft or prerelease, both updater manifests reference this fork's public signed assets, and the release is Latest.
